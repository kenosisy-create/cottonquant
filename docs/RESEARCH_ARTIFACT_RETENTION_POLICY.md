# CF 研究产物保留策略

## 1. 目的

控制全历史派生产物按日重复写入造成的空间膨胀，同时保留官方输入、raw
血缘、关键研究结论和可复算审计证据。

本文件先定义规则，不授权立即批量删除。任何首次清理都必须先生成 dry-run
清单，并由人工确认。

## 2. 数据分级

### A 级：不可自动删除

- `data/incoming/**` 中的官方、iFinD 和人工补充源文件。
- `data/raw/**`、raw snapshot、manifest 和 SHA256 记录。
- 生产核心输入对应的合同规则、官方交易日历及来源说明。
- 无法从其他保留文件确定性重建的人工复核记录。

允许做校验和去重研究，但同内容去重前必须证明 manifest 仍可追溯到唯一保留载荷。

### B 级：当前规范事实表

- `data/core/**` 下的规范化 Parquet。
- 合约映射、交易映射和必要的版本化规则快照。

规范事实表使用原子替换或明确分区更新。覆盖当前视图前必须保留输入血缘和构建 manifest；
重大 schema 变更需冻结迁移前快照。

### C 级：研究证据与正式结论

- 正式历史证据、事件研究、证据门控和策略比较结果。
- 对应 manifest、参数、warning、人审记录和中文报告。
- 已被阶段决策引用的关键产物。

保留规则：

- 每个模块保留一个 canonical latest 指针或固定名称视图。
- 保留月末快照和明确被研究报告、阶段决策引用的快照。
- 参数、代码版本、schema 或结论状态变化时额外冻结快照。
- 不用“最新文件名”替代 manifest 中的输入路径和 checksum。

### D 级：可再生成的运行产物

- `runs/daily/**` 下未被正式报告引用的旧探针和重复运行。
- 与保留 Parquet 内容相同、仅供临时检查的大型 CSV/JSON。
- 缓存、临时日志和 Dashboard 中间文件。

此级可以进入清理候选，但必须先确认：

1. 来源输入仍属于 A/B 级保留范围。
2. 生成代码和参数可识别。
3. 至少一个 canonical Parquet 或正式报告仍然存在。
4. 文件未被 manifest、阶段决策或发布报告引用。

## 3. 推荐写入模式

| 产物类型 | 推荐模式 | 不再推荐 |
| --- | --- | --- |
| Core 日表 | 按主键增量更新并原子替换规范视图 | 每日复制一份完整 core |
| 全历史研究表 | canonical latest + 月末/决策快照 | 每个交易日保存完整历史 CSV 和 Parquet |
| 事件明细 | 按事件日期分区或增量合并 | 每日重写所有历史事件的多种格式 |
| 日报 | 按交易日保留 Markdown/JSON 和 manifest | 同日多次探针全部永久保留 |
| 人工审阅 CSV | 只在需要人工查看时生成 | 默认给每个研究表同时写大型 CSV |
| 图表/发布包 | 保留正式采用版本 | 所有调试版本永久保留 |

## 4. 清理流程

首次执行按以下顺序进行：

1. 扫描文件路径、大小、日期、checksum 和 manifest 引用。
2. 输出候选清单，标记 `KEEP`、`REGENERABLE`、`REFERENCED`、`UNKNOWN`。
3. 对 `UNKNOWN` 一律不删除。
4. 人工批准后只处理 `REGENERABLE`。
5. 移动到隔离区后复跑连续性检查和关键研究入口。
6. 保留清理 manifest，确认无误后再处理隔离区。

清理工具默认必须是 `--dry-run`，执行删除需要显式参数。不得以目录修改时间代替
manifest 引用或业务日期判断。

## 5. 当前迁移顺序

1. 先统计占用最大的全历史重复模块，不删除文件。
2. 为一个低风险模块实现 canonical latest 和月末快照。
3. 验证日更、历史复算和报告引用均正常。
4. 扩展到其他研究模块。
5. 最后才生成历史冗余文件的 dry-run 清单。

在 canonical/latest 机制和引用扫描器落地前，现有研究文件保持不动。
