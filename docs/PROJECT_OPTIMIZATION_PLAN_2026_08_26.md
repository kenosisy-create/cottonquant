# Cottonquant 工程优化执行计划

## 1. 目标

本轮优化只解决可复算性、日更编排、代码可维护性和研究产物膨胀问题，
不改变 CF 研究方法、因子定义、历史结论或证据晋级门槛。

优化后的工程仍然是“CF 策略可问责研究工作台”，不是自动交易平台。

## 2. 不可破坏边界

每个优化包都必须同时满足以下条件：

1. 现有公开 CLI 命令名称和参数默认行为保持兼容。
2. T 日信号不得早于 T+1 执行，且不得获得 T 到 T+1 的收益。
3. 连续合约只作信号对象；成交、成本和持仓仍使用真实合约。
4. latest-only 输出不得读取 forward return 或其他未来标签。
5. `data/incoming`、`data/raw`、raw manifest 和输入血缘不得被自动删除。
6. R93R 的证据门槛不得因候选未通过而降低；探索层和正式晋级层必须分开。
7. 重构前后的关键研究产物必须能进行字段、行数、日期和数值等价性比较。
8. 核心代码继续使用中文注释，研究结论继续保留人工复核和非交易指令边界。

若出现无法解释的基线差异，当前优化包立即停止，不继续叠加后续改动。

## 3. 优化包顺序

### OPT-01：环境、基线与产物规则

状态：已完成。

交付：

- 使用 Python 3.12.10 作为当前复算基线。
- 提交 `uv.lock`，记录完整依赖解析结果和包校验和。
- 建立研究产物分级保留规则。
- 记录优化前测试、Ruff、关键日更专项测试和工作树状态。

退出条件：

- `uv lock --check` 通过。
- 全量 pytest 与 Ruff 通过。
- 依赖安装和保留规则有明确文档。

### OPT-02：Python 日更编排器

状态：已完成。

目标：把日更和周更的步骤依赖、失败策略和运行摘要迁回可测试的 Python 层。

设计：

- 新建轻量 `operations` 包，使用有序步骤注册，不引入第三方工作流平台。
- 步骤契约至少包含 `step_id`、依赖、是否阻断、输入检查和结果摘要。
- 默认日更只运行官方文件接入、core 刷新、连续性检查和主研究简报。
- 周更、历史证据和退役审计必须显式启用。
- PowerShell 继续负责 Windows 参数接收、Python 启动和用户可读输出。
- 默认轻量日更由 Python 编排器执行；需要历史研究、发布包或清理时，旧
  PowerShell 编排路径继续通过显式开关保留，可用
  `-UseLegacyPowerShellOrchestrator` 强制选择旧路径。

退出条件：

- Python runner 有步骤顺序、失败阻断、可选步骤和幂等测试。
- PowerShell 变为薄包装后，现有入口参数仍然兼容。
- 真实日更与旧入口的关键产物一致；2026-08-27 已完成真实 CF 日更验证。
- 期权历史源文件按 SHA256 增量接入，未变化文件不重复解析。
- signal matrix 的索引优化与原全量结果逐字段等价。

### OPT-03：CLI 按命令域拆分

目标：降低 `cli/main.py` 和 `test_cli.py` 的单文件复杂度。

顺序：`strategy` -> `dashboard` -> `data/ingest/core` -> `research`。

约束：

- `main.py` 最终只负责 Typer app 组装和顶层错误处理。
- 先移动命令实现和测试，不改变命令名、选项名、默认值或 JSON 输出。
- 退役 shadow 命令移动到明确的 legacy/audit 分组并显示弃用说明，保留复算能力。

退出条件：

- CLI help 快照和现有 CLI 测试通过。
- 每次只迁移一个命令域，禁止一次性移动全部命令。

### OPT-04：轻量产物 I/O 公共层

目标：消除路径、CSV/Parquet/JSON、warning 和 manifest 写入的机械重复。

设计：

- 使用组合式函数和小型数据契约，不建立深继承基类。
- 第一阶段只覆盖新模块；第二阶段在修改旧模块时逐步接入。
- writer 不参与统计计算，也不推断研究结论。

退出条件：

- 原子写入、校验和、warning、manifest 和路径命名有独立测试。
- 迁移模块前后产物内容等价。

### OPT-05：研究模块渐进分域

目标：逐步形成 `trend`、`options`、`fundamentals`、`evidence`、`reports` 等领域边界。

约束：

- 禁止一次性移动约 90 个文件。
- 只有在模块正在修复或明确进入下一项研究时才迁移。
- 通过兼容导入层维持旧路径至少一个优化周期。
- 优先把计算与 Markdown/JSON 渲染拆开，再考虑移动目录。

### OPT-06：验证能力和文档收敛

交付：

- 加入包含换月、缺值、异常持仓和期权低流动性的真实结构 fixture。
- 静态类型检查先覆盖公共契约和新增模块，再逐步扩大。
- README 缩减为项目定位、快速开始、日更入口和文档索引。
- 两套 Dashboard 明确保留一套；数据读取层复用，模板与 Python 分离。

## 4. 执行节奏

每个优化包独立提交，不与新研究因子混合。每包按以下顺序执行：

1. 冻结当前接口和关键产物基线。
2. 只做一个边界内的机械改造。
3. 运行专项测试、全量测试和 Ruff。
4. 用真实 core 数据执行非破坏性 dry-run。
5. 比较关键产物并记录差异。
6. 通过后再合并；不通过则停在当前包诊断。

日常 CF 数据更新可以继续，不需要等待全部优化完成。新因子扩张暂缓到 OPT-02
完成，以免继续扩大 PowerShell 编排和巨型 CLI。

## 5. 成功标准

- 日更入口更快定位失败步骤，并能在 Python 测试中复现编排行为。
- 公开 CLI 保持兼容，研究结果没有无解释漂移。
- 全历史派生产物不再按每个交易日无限完整复制。
- 新增研究模块不再重复实现整套产物写入逻辑。
- 退役能力不出现在默认主线，但历史证据仍可复算。
- 代码目录和 README 能让研究人员快速找到数据、方法、证据和运行入口。

## 6. 明确不做

- 不因工程优化重新搜索因子阈值。
- 不因 R93R 负面结果降低正式证据门槛。
- 不启动 OMS、自动下单、实盘执行或多品种平台化。
- 不直接删除 `data/incoming`、`data/raw`、manifest 或历史审计证据。
- 不把全部模块同时改名、移动或重写。
